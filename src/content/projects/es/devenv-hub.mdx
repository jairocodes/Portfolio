El sistema de templates funciona como un "Spring Initializr" solo por CLI: cada template declara sus opciones (versión de runtime, si incluye Postgres/Redis, tipo de servidor) en un `template.yaml`, y el comando `devenv up` las pregunta interactivamente o las recibe todas de una vez con `--set key=value --yes` para uso en scripts.

El rol de administrador no tiene un endpoint para "promoverse" a sí mismo — se bootstrapea por una allowlist de emails (`ADMIN_EMAILS`) que promueve automáticamente en el siguiente login, evitando abrir una superficie de escalamiento de privilegios innecesaria.
